This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Sales/landing page for **JA Manager**, live at **https://jam.jeitoagape.com.br** (the app itself is `app.jeitoagape.com.br`; the band site owns the root `jeitoagape.com.br`), a music-repertoire management app (cifras/transposition, setlists, escalas, projeção, ensaios). The page is in **pt-BR**. Title: **"JA Manager — repertório, escala, ensaio e telão num app só"**; hero: **"Seu grupo musical chega pronto a cada evento."**

**Copy is checked against the app.** Every feature claim on the page must be true in the app *today*. Sources of truth, in order: `../JAM.jeito-agape.VUE/src/data/changelog.js` (the user-facing record), `../JAM.jeito-agape.VUE/PRODUCT.md`, `../JAM.jeito-agape.LOPS/CLAUDE.md`. Things the page deliberately does **not** claim because they are not built: "Health Score"/team-health percentages, live transposition that every device follows (Palco sincronizado, planned), customer counts or testimonials. The proof list ("Feito por quem toca toda semana") shows real versions with real dates — refresh it from `changelog.js` when the app ships something sellable. Chords in the mockups use the app's own notation (`C`, `D`, `F#m`), not "Lá/Ré".

**Positioning (keep it):** lead with the *product/features*, not religion. Primary audience is church worship teams, but copy speaks to **grupos musicais e bandas** of any kind. **Customer-facing copy says "grupo musical" (or "grupo"), never "ministério"** — owner, 2026-11-16, to keep the page generic; "Ministério Jeito Ágape" stays as the band's name and `#obra` still describes it as a ministry — evangelical- *and* catholic-friendly, never Catholic-only terms; the ministry the app was born in is focused on **events** (never "banda para missa"). Since 2026-11 the page has a full section **`#obra` — "Sua assinatura sustenta uma obra."** (owner's request): the app was built inside the **Jeito Ágape** ministry and the subscription funds it.

## Architecture

The sales page is one file: [index.html](index.html) (~140 KB) — HTML + one `<style>` in `<head>` + one `<script>` at the end. Since lot A3 (2026-11-16) four secondary pages sit beside it — `comecar/` (sign-up form), `comecar/pronto/` (back from the card page), `termos/` and `privacidade/` (drafts) — sharing [assets/css/paginas.css](assets/css/paginas.css) (the index's tokens; the index does not use it). See "Sign-up with card" below. **No build step, no framework, no dependencies.** The 2026-11 version was **generated from the design proposal** (claude.ai design canvas "JAM — nova landing page (funil de vendas)", 2026-11-14…16) and is now the source of truth: edit `index.html` directly. Most styling is **inline** (`style="…"`) as it came out of the canvas; the `<style>` block holds what inline styles cannot do (hover, media queries, the carousel, the FAQ, `.so-largo`/`.so-estreito` breakpoint helpers at 1000 px).

**Look:** graphite ground `#0B0B0D`, surfaces `#141416`/`#17171B`, 1 px borders `#1F1F25`/`#2A2A31`, text `#F4F4F6`/`#B4B4BE`, one accent — the app's **rose `#E11D48`** (text-on-dark tint `#FF637E`) — replacing the old dark-neon violet theme and the EQ presets (both removed). The `#obra` section is the only light surface (`#FBF7F5`).

**Type (owner's pick, 2026-11-16: "mais arredondada, limpa e fina"):** headings **Quicksand 500** and body **Source Sans 3**, set as CSS variables on the root `div` (`--f-titulo`, `--f-texto`, `--w-titulo`, `--ls-titulo`; `h1,h2,h3,.f-titulo` read them). Changing the pairing = those four variables + the Google Fonts `<link>`. Running text (`p`, `dd`) is **justified with hyphenation** (`hyphens: auto`, `lang="pt-BR"`), owner's request; short card texts stay left-aligned. Mono only for data (chords over lyrics, the import URL).

**Brand mark:** the **same heart as the band site's favicon**, redrawn as a vector and recolored (rose fading to `#6D4458`) — inline SVG in the menu/footer; `assets/favicon.svg` (transparent, lighter gradient under `prefers-color-scheme: dark`), `assets/favicon-32.png`, `assets/apple-touch-icon.png` (on black, iOS needs a background). Never the app's symmetric heart.

**Sections in order:** sticky menu "Setlist" (numbered sections + reading-progress line; hamburger `<details>` on phones) → hero with a **carousel of six real app screens** (`[data-carrossel]`: Home, Palco, Ensaio, Escala, Plano de ensaio, Telão; tabs with a 6 s progress bar, arrows, pause; autoplay off under reduced motion and after any manual navigation; phone screenshots below 1000 px) → trust strip → `#semana` (five aligned cards, one per moment of an event, each with a slice of the app) → `#recursos` with feature rows `#cifra #importar #partitura #escala #ensaio #palco #coordenacao` (sides alternating) → "Também vem junto" → proof (versions) → `#planos` (monthly/annual toggle) → `#obra` → `#perguntas` (9 `<details>`; the JSON-LD `FAQPage` repeats them — change both together) → final CTA → footer.

**Interactive bits** (the script at the end): elements with `data-tpl` carry `data-t-<attr>="… [[key]] …"` templates; `data-acao` buttons flip `estado` (`anual`, `partitura` G/A, `importar` link/nome) and the script re-applies the values (`BASE`/`VARIANTES` tables). Then the menu (current section, progress line, closing the phone menu) and the carousel.

**Screenshots** (`assets/img/telas/*.webp`, computer 2880×1800 and phone 1170×2532) are captures of the **local dev app** with the dev fixtures (`scripts/ui-screenshots` in LOPS, frozen clock) — never production data — with sample texts swapped for the showcase (Missa → casamento, test lyrics → invented lines, role-like names → common names). Re-capture when the app's look changes.

## Sign-up with card (`JAM_SIGNUP`, lot A3)

Plan of record: `~/development/labs/control-tower/docs/PLAN-2026-11-16-subscriptions.md` (§1 flow, §3.2 the Tower route and its answers, §3.11 this site, §6 decisions D4/D6/D13). Flow: CTA → `comecar/?plano=<cantor|banda|igreja>&ciclo=<mensal|anual>` → form → `POST JAM_SIGNUP.url` (the Tower's public `/api/signups`) → `{ checkout_url }` → AbacatePay's card page (R$ 0,00) → `comecar/pronto/`. The Tower creates the group in the JAM and the JAM e-mails the "crie a sua senha" link.

- **The flag:** `window.JAM_SIGNUP = { url: '', turnstile: '' }` in the `<head>` of **both** `index.html` (next to `JAM_ANALYTICS`) and `comecar/index.html` — same values in both. **`url` empty = off**: the index renders exactly as before (checked pixel-identical to `main` at 1440/390 px on 2026-11-16) and `/comecar/` shows a short note and the WhatsApp button (carrying `?plano`/`?ciclo`) instead of the form. Never commit a filled `url` before the go-live; test by injecting it (e.g. puppeteer `evaluateOnNewDocument` with a non-writable `window.JAM_SIGNUP`).
- **How the index switches** (the page's own template mechanism): `estado.cadastro = !!JAM_SIGNUP.url`. `BASE` holds today's values — the six CTA hrefs (`ctaMenu`, `ctaHero`, `ctaCantor`, `ctaBanda`, `ctaIgreja`, `ctaFinal`), `ctaAlvo` (`_blank`) and the trial texts (`heroNota`, `planosIntro`, `faq1`, `faq2`), equal to the static HTML. `VARIANTES.cadastro` has the card texts and the `comecar/` links (menu/hero/final → `comecar/`, i.e. Banda mensal; plans → `?plano=…&ciclo=mensal`), `VARIANTES.cadastroAnual` the plan links with `ciclo=anual`, so the plan CTAs follow the monthly/annual toggle. With the flag on, `aplicar()` runs once at load; a template that evaluates to `''` **removes** the attribute (that is how `target="_blank"` goes). `[data-so-cadastro]` elements (footer "Termos de uso"/"Privacidade") are `hidden` unless the flag is on. "Tirar uma dúvida no WhatsApp" and the footer WhatsApp stay on WhatsApp. Editing a trial text = the static HTML **and** `BASE` (off) or `VARIANTES.cadastro` (on); the card FAQ texts are repeated in the A8 comment after the JSON-LD.
- **`comecar/` switches** with no flash: the head sets `<html data-cadastro>` when `url` is filled; CSS hides `.so-cadastro` without it and `.sem-cadastro` with it.
- **The form** (`comecar/index.html`, all logic in its end script): group name (1–150), e-mail (≤ 254), plan cards with the price (from `PLANOS` in the script — must match the Tower's `products.signup_plans`, decision D10) and the cycle pills, a summary ("Hoje: R$ 0,00. A partir do 8º dia: …"), terms checkbox (links open in a new tab), the honeypot `website` (off-screen, `tabindex=-1`), Turnstile **only when `JAM_SIGNUP.turnstile` is set** (explicit render, dark, `size: flexible`; reset after every refusal because a token is single-use). Client checks first; then a confirm step shows the e-mail back ("Vamos mandar o acesso para …") before anything is sent. Body, exactly: `{ product: 'jam', group_name, email, plan: CANTOR|BANDA|IGREJA, cycle: monthly|yearly, accepted_terms, turnstile_token, website }`, JSON, no credentials, 20 s timeout. Answers: 201/200 with an **https** `checkout_url` → redirect (anything else is treated as "fora"); 400 → the Tower's `error` under its `field`; 409 → D4 text on the e-mail ("Este e-mail já tem conta no JA Manager. Entre no app ou use outro e-mail.", "Entre no app" links to the login); 429 → "Tente de novo em N minutos" from `Retry-After` (or `retry_after` in the body), generic wait text when unreadable; 503/other/network → "Não conseguimos abrir o cadastro agora. Tente de novo em instantes ou fale com a gente no WhatsApp." with the WhatsApp link. Coming back from the card page with the browser's back button resets the "Abrindo…" state (`pageshow`).
- **GA4 events** (never e-mail or group name): `signup_click` (`cta_location`, `plano`) on CTAs that lead to `comecar/` — replaces `whatsapp_click` on those buttons only while the flag is on (the index listener reads the href at click time); `signup_started` (`plano`, `ciclo`) when the form opens; `signup_submitted` (`plano`, `ciclo`, `transport_type: beacon`) before the redirect (waits ≤ 1.2 s for gtag's callback, goes at once when gtag.js is blocked); `signup_error` (`motivo`: `campo` 400 · `email` 409 · `limite` 429 · `fora` 503/network/bad answer — Tower answers only, not the client-side checks); `signup_card_done` on `comecar/pronto/` (once per tab, `sessionStorage`). The new pages' WhatsApp links fire `whatsapp_click` with `cta_location` `cadastro`, `cadastro-erro` or `pronto`.
- **Pages:** `comecar/` (in the sitemap), `comecar/pronto/` (`noindex`; the owner's text "Cartão cadastrado. Enviamos para o seu e-mail o link para criar a senha. Não chegou em 5 minutos? Fale com a gente."), `termos/` and `privacidade/` — **drafts**: "RASCUNHO — revisar antes de publicar" banner, `noindex, nofollow`, highlighted `[preencher: …]` (razão social, CNPJ, endereço, e-mail de contato, encarregado, data…) and `[conferir: …]` points for the owner and a lawyer/accountant; long text on the `#obra` light surface. GA4 loads on `comecar/` and `comecar/pronto/` (same `JAM_ANALYTICS` literal as the index), not on the drafts.
- **Go-live (lot A8), besides filling `url` and `turnstile` in both files:**
  1. Owner + lawyer/accountant finish `termos/` and `privacidade/`: every `[preencher]`/`[conferir]` answered, banner removed, `robots` → `index,follow`, both added to `sitemap.xml`.
  2. Make the card copy the **static** copy (move `VARIANTES.cadastro` texts into the HTML and `BASE`): AI crawlers that do not run JS (GPTBot, ClaudeBot…) read the static HTML. Swap the JSON-LD as the "VIRADA DO CADASTRO" comment after it says (FAQ 1–2, `offers` → `InStock` + `comecar/` url).
  3. `llms.txt`: replace "Hoje o teste começa pelo WhatsApp…" with the card model; footer: `Razão social · CNPJ`.
  4. Tower side: `signup_origin` = `https://jam.jeitoagape.com.br`, `signup_plans` prices = `PLANOS`, `completionUrl` → `https://jam.jeitoagape.com.br/comecar/pronto/`, and **`Access-Control-Expose-Headers: Retry-After`** on the 429 (a cross-origin page cannot read `Retry-After` otherwise).
  5. GA4: register the event dimension `ciclo`; mark `signup_card_done` as a key event in place of `whatsapp_click`.
  6. Update this file (the "live copy still says WhatsApp" paragraph above).

## Deploy — GitHub Pages

Every push to `main` runs `.github/workflows/pages.yml`: it copies `index.html`, `robots.txt`, `sitemap.xml`, `llms.txt`, `CNAME`, `assets/`, `comecar/`, `termos/` and `privacidade/` into `_site` (a new top-level page folder must be added to that list) and deploys it with `actions/deploy-pages`. Custom domain `jam.jeitoagape.com.br` (`CNAME` + the repo's Pages setting); DNS in **Cloudflare**, `CNAME jam → ja-music.github.io`, **DNS only** (grey cloud) so GitHub issues the HTTPS certificate. *Gotcha:* if the custom domain is saved before the DNS record exists, no certificate is requested — remove the domain and add it back (`echo '{"cname":null}' | gh api -X PUT repos/ja-music/JAM.jeito-agape.LANDING/pages --input -`, then `-f cname=jam.jeitoagape.com.br`). Small fixes go straight to `main`; a redesign goes through a PR (there is no preview environment — check locally first).

## Editing rules

- All asset paths **relative** (site may be served from a subpath).
- Copy: keep the inclusive positioning above; product voice is "direto, prático" (not the band's warm-Catholic voice). Headings say plainly what the section is, short sentences, `você`, feature names as the app calls them (Tocadinha, Cronograma, Lâminas, Mural de recados, Caixa), no puns, no competitor names. Before adding a claim, find it in `changelog.js` or `PRODUCT.md`.
- No eyebrow labels above headings, no glyph icons (inline SVG only), contrast ≥ 4.5:1 for text.
- Images: WebP, with `width`/`height`; only the first carousel slide loads eagerly.
